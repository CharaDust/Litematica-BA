## 1. 项目概述
### 1.1 项目名称
**Litematica Blueprint Assistant（简称：Litematica BA）**
### 1.2 项目定位
一款面向 Minecraft `*.litematic` 投影文件的本地管理与分析工具，目标是在不启动游戏的前提下完成文件管理、属性读写、统计分析、分层展示与渲染输出。
### 1.3 名称释义
- **BA**：Blueprint Assistant 的缩写
- **BA（影射）**：同时影射“蔚蓝档案（Blue Archive）”首字母
### 1.4 易混淆术语声明
- **预览图**：文件内 `PreviewImageData` 数组表示的图像
- **缩略图**：本软件渲染得到的 PNG 图像（亦称渲染图）
### 1.5 核心价值
1. **离线管理**：无需启动游戏即可管理投影文件
2. **统一入口**：以“激活文件”驱动各模块协同
3. **可视化能力**：支持预览图处理、区域渲染、分层展示与材料统计

#### 2.2.3 文件交互
| 项 | 说明 | 优先级 |
|----|------|--------|
| 顶部按钮 | 重命名、移动到回收站、发送到文件夹（库内目录） | P0 |
| 激活文件 | 双击 `.litematic` 激活；单击行右侧提供激活按钮 | P0 |
| 未保存确认 | 激活切换前若有未保存内容需确认 | P0 |

### 2.8 模块八：材料列表（独立窗口，优先）
#### 2.8.1 功能描述
展示投影文件在不同上下文（整体/层级/区域/外部文件）下的材料列表，采用缓存优先 + 后台异步刷新策略。
#### 2.8.2 缓存与调度
| 项 | 说明 | 优先级 |
|----|------|--------|
| 异步预加载 | 选定文件后立即后台加载材料列表 | P0 |
| 切换挂起 | 加载中切换文件时，旧任务挂起，新文件优先 | P0 |
| 缓存目录 | 缓存写入 `data/cache` | P0 |
| 缓存主键 | 使用完整文件路径作为主键 | P0 |
| 失效判定 | 文件在软件外部被改动则缓存失效 | P0 |
| 缓存读取策略 | 若存在缓存，优先读取缓存（即使已失效），并以灰色文本展示 | P0 |
| 刷新策略 | 缓存展示后立即后台异步重算，完成后替换为最新内容 | P0 |
#### 2.8.3 工作簿（Line.1）
“工作簿”下拉框位于独立窗口第一行，宽度占整行，用于切换材料列表语义视角。切换工作簿不会清空工作簿数据对象，仅切换当前展示与数据来源。
| 工作簿项 | 说明 | 优先级 |
|----------|------|--------|
| 整个投影 | 基于当前激活文件统计全部区域材料 | P0 |
| 选定层级 | 基于当前层级条件统计材料 | P1 |
| 选定区域 | 基于当前选中子区域统计材料 | P0 |
| 自定义文件 | 直接从 CSV 打开材料列表，不依赖当前投影统计流程 | P1 |
#### 2.8.4 功能按钮组（Line.1，靠左）
| 控件 | 行为 | 优先级 |
|------|------|--------|
| 重新加载 | 将当前缓存标记为“已失效”，并重新从投影文件加载当前工作簿数据 | P0 |
| 重新加载（自定义文件模式） | 当工作簿为“自定义文件”时，该按钮替换为“浏览材料列表...”并用于选择 CSV 文件 | P0 |
| 写入文件 | 弹出保存对话框，导出当前表格 | P0 |
| 倍数输入框 | 支持上下调节，用于控制列表正文材料数量的倍数显示 | P0 |
“写入文件”对话框文案与格式选项：
- 你想将该材料列表保存为？
- ASCII 艺术表文件（`.txt`）
- 逗号分隔值表（`.csv`）
#### 2.8.5 列表正文
| 表头 | 说明 | 优先级 |
|------|------|--------|
| 图标 | 方块图标列。默认 2D；可切换 3D（首版非优先） | P0/P2 |
| 名称 | 默认显示标准译名；右键该行可切换表头语义为“方块ID” | P0 |
| 总计 | 显示统计总数量 | P0 |
图标显示扩展设置（非优先）：
- 设置项：`方块图标渲染模式`（`2D`/`3D`，默认 `2D`）
- 首次切换至 `3D` 时，从 Minecraft Wiki 下载所需图标资源
#### 2.8.6 悬浮浮窗（跟随鼠标）
当鼠标悬浮在列表项时，显示跟随鼠标的浮窗，包含：
- **项目**：同一行显示图标与译名
- **ID**：显示方块 ID
- **总计**：显示可拆解统计值，格式为  
  `总数 = 组数 x 64 + 余数 = 盒数 潜影盒`
计算规则：
- `组数 = 总数 / 64`（舍弃小数）
- `余数 = 总数 % 64`
- `盒数 = 总数 / 1728`（保留 2 位小数）
- 浮窗内变量数字使用加粗样式
相关设置项：
- `材料统计数字计算时机`：`预计算` 或 `即时演算`
  - `预计算`：在列表数据生成阶段先算好浮窗数字
  - `即时演算`：悬浮时按当前总数动态计算

## 4. 数据模型（草案）
### 4.1 核心实体关系
```
┌──────────────────────┐
│ SchematicFile        │
├──────────────────────┤
│ id                   │
│ full_path (unique)   │
│ file_name            │
│ file_version         │
│ mc_data_version      │
│ author               │
│ description          │
└──────────────────────┘
          │
          ├──────────────┐
          ▼              ▼
┌──────────────────┐   ┌──────────────────────┐
│ MaterialCache    │   │ RenderCache          │
├──────────────────┤   ├──────────────────────┤
│ file_path(pk)    │   │ file_path(pk)        │
│ region_key       │   │ region_key           │
│ payload_json     │   │ thumbnail_path       │
│ cache_mtime      │   │ preview_written      │
└──────────────────┘   └──────────────────────┘
```
### 4.2 关键字段
| 字段 | 含义 |
|------|------|
| `full_path` | 文件完整路径，作为缓存索引基础 |
| `cache_mtime` | 缓存生成时的源文件时间戳 |
| `payload_json` | 材料统计/图表等可复用计算结果 |

## 5. 系统架构（草案）
### 5.1 分层结构
| 层级 | 说明 |
|------|------|
| UI 层 | 导航、表单、渲染视图、异步状态展示 |
| 业务层 | 激活文件上下文、SNBT 读写、统计与渲染调度 |
| 数据层 | 文件系统访问、设置管理、缓存管理 |
| 适配层 | legacy 与外部渲染方案适配 |
### 5.2 关键约束
1. 文件解析、统计与渲染必须异步化，避免阻塞 UI。  
2. “属性（Properties）”是活动文件管理主入口。  
3. 缓存采用“先展示后刷新”策略，保证反馈速度。

| 风险 | 影响 | 概率 | 应对措施 |
